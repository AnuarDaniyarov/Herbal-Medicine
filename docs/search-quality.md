# Качество поиска (MVP)

## Цель

Показать, что платформа находит **уже имеющиеся** проверенные сведения, а не генерирует ответы. Для диплома достаточно небольшого измеримого набора запросов и ручной/автоматической проверки hit@k.

## Как устроен поиск

1. **Keyword** — совпадение токенов запроса с title/claim_text/именами растений и препаратов среди записей со статусом `VERIFIED`.
2. **Vector (pgvector)** — при `SEARCH_VECTOR_ENABLED=true` и заполненных embeddings добавляет семантически близкие claims.
3. **Слияние** — verified claims идут первыми в `GET /api/search`; режим ответа: `keyword` | `vector` | `hybrid`.

Текущие embeddings — локальный hash-based baseline (384 dim), без внешней multilingual-e5. Это достаточно для демонстрации контура hybrid; нейросеть можно подключить позже без смены API.

## Минимальный набор запросов для проверки

| Запрос | Ожидание (hit) | Не должно |
| --- | --- | --- |
| `бессонница` | claim INDICATION про сон / валериану | выдуманные дозировки |
| `зверобой` + противопоказание / взаимодействие | claim CONTRAINDICATION или INTERACTION | ответ без источника |
| `валериана` | растение или verified claim | пустой ответ при наличии seed |
| `unicornium zzzunknown` | пустая выдача / `NO_EVIDENCE` у ассистента | домыслы |

Автоматический smoke-набор живёт в `SearchQualitySmokeTests` (keyword-контур на H2; vector в тестах отключён).

## Метрика для диплома

На ручном прогоне 20–30 запросов фиксируйте:

- **Hit@5** — доля запросов, где релевантная карточка/claim в топ-5;
- **Доля «данных нет»** на заведомо пустых запросах (должна быть 100%);
- **Доля safety-redirect** на вопросах про дозу/беременность/детей (ожидается 100% на контрольном списке).

Шаблон таблицы результатов можно приложить к пояснительной записке.
