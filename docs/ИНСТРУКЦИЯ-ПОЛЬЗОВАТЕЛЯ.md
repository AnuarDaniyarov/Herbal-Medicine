# Руководство пользователя Herbarium AI

## 1. Назначение

Herbarium AI — исследовательский прототип для изучения связей между растениями, образцами и экстрактами, химическими соединениями, источниками и экспериментальными измерениями. Платформа также позволяет запросить ограниченную вычислительную оценку и сравнить кандидатов.

Результат модели — гипотеза для дальнейшей проверки. Система не ставит диагноз, не назначает лечение и не доказывает эффективность или безопасность препарата.

## 2. Требования

- Docker Desktop с Docker Compose — для быстрого запуска PostgreSQL и backend;
- Java 21 и Maven Wrapper — если backend запускается напрямую;
- Node.js 22.22.3+ или 24.15+ и npm — для Angular frontend;
- браузер; интернет нужен для загрузки Bootstrap CSS через CDN.

## 3. Первый запуск на Windows с Docker

Откройте PowerShell в корне проекта:

    cd C:\Users\User\IdeaProjects\medicine-platform

Скопируйте шаблон настроек и задайте локальный пароль в файле .env:

    Copy-Item .env.example .env

Не публикуйте .env и не коммитьте пароли. Запустите базу и backend:

    docker compose up --build -d
    docker compose ps
    docker compose logs -f backend

Откройте отдельное окно PowerShell и запустите Angular:

    cd C:\Users\User\IdeaProjects\medicine-platform\frontend
    npm ci
    npm start

Откройте приложение и API:

- Angular: http://localhost:4200
- Spring Boot API: http://localhost:8081
- Swagger UI: http://localhost:8081/swagger-ui.html
- OpenAPI JSON: http://localhost:8081/v3/api-docs

Остановить сервисы без удаления базы:

    docker compose down

Не используйте команду docker compose down -v, если хотите сохранить базу: ключ -v удаляет volume с данными PostgreSQL.

## 4. Запуск без Docker

Создайте в PostgreSQL базу medicine_platform. Задайте переменные окружения в PowerShell, заменив пароль на свой:

    $env:DB_URL = 'jdbc:postgresql://localhost:5432/medicine_platform'
    $env:DB_USERNAME = 'postgres'
    $env:DB_PASSWORD = 'ваш-локальный-пароль'
    $env:CORS_ALLOWED_ORIGINS = 'http://localhost:4200'
    .\mvnw.cmd spring-boot:run

В другом окне:

    cd frontend
    npm ci
    npm start

Spring Boot применяет миграции Flyway автоматически. Angular dev server проксирует запросы /api в backend на порт 8081 через frontend/proxy.conf.json.

## 5. Работа с платформой

### Растения

1. Откройте раздел «Растения».
2. Ищите по научному названию или семейству.
3. Используйте пагинацию, чтобы просмотреть другие страницы.
4. Откройте карточку и изучите связанные образцы, экстракты и соединения, если они есть.

Пустое поле означает, что сведения отсутствуют в доступной записи. Не делайте вывод о составе или свойствах растения по отсутствующим данным.

### Соединения

1. Откройте «Соединения».
2. Ищите по названию, SMILES или внешнему идентификатору.
3. При необходимости отфильтруйте записи по статусу структуры.
4. Откройте карточку и изучите структуру, ботанические связи, источники и измерения активности.

Статус UNVERIFIED означает, что запись не прошла полную проверку структуры. Наличие соединения в каталоге само по себе не подтверждает лечебный эффект.

### Сравнение и CSV

1. В каталоге соединений нажмите «Сравнить» рядом с нужными записями.
2. Откройте «Сравнение» в навигации.
3. Проверьте активность и assay, к которым относятся результаты.
4. Используйте экспорт CSV для дальнейшей исследовательской обработки.

Не сравнивайте напрямую результаты разных assay или единиц измерения без обоснованного преобразования.

### AI-оценка

1. Откройте «AI-оценка».
2. Выберите тип оценки. Текущий ML-baseline ограничен сценарием человеческой AChE IC50; другие типы могут возвращать DEMO.
3. Введите SMILES структуры и отправьте форму.
4. В результате проверьте статус, вероятность, версию модели и предупреждения.

Модель обучена на 74 записях: 58 использованы для обучения, 16 — для случайной тестовой выборки. Разделение не выполнено по химическим каркасам. Данные и структуры не прошли полную независимую верификацию. Метрики нестабильны и не доказывают переносимость на новые вещества.

## 6. Что такое SMILES

SMILES (Simplified Molecular Input Line Entry System) — текстовая запись химической структуры. Она компактно описывает атомы и связи между ними. Это не название вещества и не обычный текстовый запрос.

Примеры:

| Пример | SMILES | Объяснение |
| --- | --- | --- |
| Этанол | CCO | Углерод, углерод и кислород соединены последовательно |
| Уксусная кислота | CC(=O)O | Скобки задают ветвь, знак равенства — двойную связь |
| Бензольное кольцо | c1ccccc1 | Строчная c обозначает ароматический атом; цифра замыкает кольцо |

Основные символы:

- C, N, O, S обозначают атомы; строчные c, n обычно обозначают ароматические атомы;
- = и # обозначают двойную и тройную связь; одинарная связь часто опускается;
- круглые скобки обозначают ветвление;
- одинаковые цифры указывают на замыкающую связь кольца;
- квадратные скобки уточняют атом, например заряд или изотоп;
- @ и @@ могут задавать пространственную конфигурацию атома.

Одну молекулу можно представить несколькими эквивалентными SMILES. Каноническая форма зависит от алгоритма нормализации. Форматная проверка строки не является полноценной химической валидацией. Перед анализом проверьте структуру химическим ПО. Корректный SMILES не гарантирует, что модель обучалась на похожих структурах или применима к соединению.

## 7. Как трактовать данные

- Эксперимент — результат конкретного теста с единицей и источником.
- Импортированная запись — сведения внешнего набора данных; статус может быть непроверенным.
- AI-оценка — вычислительный результат с типом активности, моделью, версией и предупреждениями.
- DEMO — демонстрационный ответ, а не научный результат.

Не смешивайте эти типы данных. Прогноз не становится экспериментальным измерением.

## 8. Frontend и микросервисы

Frontend использует отдельные API-клиенты по предметным областям:

- PlantApiService — растения, образцы, экстракты;
- CompoundApiService — соединения и измерения;
- ResearchApiService — тесты, мишени и источники;
- PredictionApiService — оценка и сохранённые результаты;
- CandidateApiService — сравнение и CSV;
- ApiService — фасад, которым пользуются страницы приложения.

Сейчас все клиенты обращаются к единому адресу /api, а proxy направляет запросы в одно Spring Boot приложение. Backend разделён на предметные Java-пакеты, но ещё не является набором отдельно развёрнутых микросервисов. Разделение frontend-клиентов упрощает будущее подключение API Gateway или разных адресов сервисов, но само по себе не создаёт backend-микросервисы. Для этого потребуется отдельно реализовать и развернуть сервисы, определить маршрутизацию, авторизацию и обработку сетевых ошибок.

## 9. Bootstrap

В frontend подключён Bootstrap 5.3.8 CSS с integrity-проверкой через официальный CDN; собственные стили Herbarium AI дополняют Bootstrap. Bootstrap JavaScript не загружается: маршрутизацией и интерактивностью управляет Angular. Для загрузки CSS браузеру нужен интернет. В изолированной сети подключите локальную копию Bootstrap вместо CDN-ссылки в frontend/src/index.html.

Документация Bootstrap: https://getbootstrap.com/docs/5.3/getting-started/download/

## 10. Частые ошибки

### PostgreSQL сообщает, что не указан пароль SCRAM

Backend не получил DB_PASSWORD. Для Docker проверьте .env и пересоздайте backend:

    docker compose up -d --force-recreate backend
    docker compose logs -f backend

### Flyway сообщает о checksum mismatch

Не редактируйте миграцию V*.sql, которая уже применялась к базе. Добавьте новую миграцию со следующим номером. Не исправляйте flyway_schema_history вручную. Flyway repair используйте только после проверки схемы и истории.

### Frontend работает, но данные не загружаются

Убедитесь, что backend доступен на порту 8081 и frontend запущен командой npm start из папки frontend. Эта команда включает proxy.

### SMILES отклоняется

Проверьте написание, скобки, цифры колец и отсутствие переноса строки. Для сложной стереохимии проверьте структуру в химическом ПО; не удаляйте символы стереохимии наугад.

### Результат имеет статус DEMO

Для выбранного activity code нет подключённой модели. Используйте такой ответ только для демонстрации UI и API.

## Регистрация, вход и первая роль администратора

Гость может просматривать общедоступные каталоги. Зарегистрируйтесь через кнопку «Регистрация»: email должен быть корректным, пароль — не короче 12 символов. Новая учётная запись всегда получает роль USER. Пароль хранится в backend в виде BCrypt-хэша.

Чтобы при первом запуске создать администратора, до запуска backend заполните локальный файл .env:

    BOOTSTRAP_ADMIN_EMAIL=admin@example.org
    BOOTSTRAP_ADMIN_PASSWORD=задайте-собственный-длинный-пароль

При старте приложения администратор создаётся только если такого email ещё нет. Значение пароля не выводится в логи. После запуска войдите на странице /login и откройте «Администрирование» → «Пользователи и роли». Там можно назначить роль EXPERT обычному пользователю. Последнего администратора система не позволит понизить до другой роли.

Если bootstrap-переменные не заданы, приложение не создаёт администратора автоматически. Не используйте примерный пароль из документации в production. Файл .env исключён из Git.

На этом этапе реализованы регистрация, вход по серверной сессии, выход и назначение ролей. Эксперт и администратор могут открыть «Проверка базы», изучить источник для каждого утверждения и утвердить или отклонить запись. Только утверждённые факты показываются в публичном API и карточке растения.

## Поиск-помощник

Войдите в аккаунт и нажмите «Помощник». Задайте вопрос по растениям или препаратам, которые внесены в базу. Ответ использует только экспертно проверенные утверждения и показывает фрагменты с DOI или ссылками на первоисточник. Если совпадений нет, помощник сообщает об отсутствии данных. Вопросы о дозировках, беременности, детях, взаимодействиях и серьёзных диагнозах получают предупреждение и направление к врачу/фармацевту.

По умолчанию сайт не подключает генеративную языковую модель: он выполняет поиск по словам и показывает выдержки из базы. Это специально отмечено в интерфейсе. Для подключения совместимой модели задайте `ASSISTANT_LLM_ENABLED=true`, `ASSISTANT_LLM_BASE_URL`, `ASSISTANT_LLM_MODEL` и, если требуется, `ASSISTANT_LLM_API_KEY` в окружении backend. Поддерживается `/v1/chat/completions`. При ошибке модели приложение возвращается к показу проверенных фрагментов. Удалённая модель получает вопрос и найденные сведения; не передавайте туда конфиденциальные данные без проверки правил проекта и провайдера.

Результат генеративной модели отмечается `LLM_RAG`/`isAiGenerated=true` и должен проверяться в рамках оценки качества. Привязка к источникам и системное требование не добавлять факты снижают риск выдумок, но не гарантируют точность сгенерированного текста. Не используйте ответ как медицинскую рекомендацию.

Последние запросы и ответы сохраняются для авторизованного пользователя и отображаются в разделе помощника. Личный список избранного пока не реализован.
